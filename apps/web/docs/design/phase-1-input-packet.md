## Isolation and preservation contract to resolve in P1-01

- Choose the smallest repository-compatible isolated local preview mechanism; declare location, lifecycle, no-index/non-production boundary, data source, ownership and eventual cleanup. This packet does not create new infrastructure or choose an implementation path on behalf of the prototype task.
- Do not change shared root/storefront tokens or rewrite live routes just to demonstrate a candidate. Avoid a second active customer system: prototype styling is explicitly isolated/removable; accepted production consumers later converge to one value/variant/state contract.
- Wholesale currently imports customer CSS and .storefront-shell (NEW-001); root 404 uses customer CSS/fonts (NEW-002); admin campaign preview shares CampaignArtwork/Outfit (NEW-003). Any actual shared change must first address these consumers and verify compatibility; isolated prototype work can proceed without incidental retheming.
- Preserve server rendering, small client boundaries, routes/query/legacy links, metadata/structured data, EN/AR/RTL, accessible native semantics, focus/touch/reduced motion and source media identity. No broad global reset or replacement styling library by default.
- No trusted client price/stock/tax/fees/discounts/final totals, no auth/RBAC bypass, checkout/provider activation, production database access or deployment. Use labelled fixtures and preserve real unavailable states. New cart persistence, if needed for a proof, must not become monetary authority.
