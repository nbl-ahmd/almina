## Corrections found through execution

- Native Escape on a search input cleared the query and reopened focused mode. Prevented that default while closing; both languages now pass.
- Submitted GET query was lost from header state. Search now remounts against pathname/query and receives the actual query.
- Error recovery initially used `reset()`, which rerendered rejected cached contents. Installed Next **16.4.2** bundled `error.md` specifies refetching `retry()`; proof now uses it and both injected failures recover without reload.
- Generic save controls now include product identity. Cart no longer presents an empty result as a read-error substitute; failed reads clear stale display and successful reads clear recovered errors.
- Render inspection caught two search focus outlines. Input outline is suppressed only inside the search field; one visible outer ring indicates input focus, while buttons retain their own keyboard outlines. Folded duplicate base CSS declarations into their owning rules; mode rules remain isolated in the proof module.
- Test sequencing was corrected to wait for the actual PDP history entry before browser Back, scope alerts away from Next's route announcer, and exercise read failure rather than incorrectly treating local removal as a server mutation.
- Screenshot automation initially altered caret styles before hydration. Captures now retain initial caret styling and wait for asserted states. The final run contains no hydration warning; initial failed/raw runs remain in ignored logs.
