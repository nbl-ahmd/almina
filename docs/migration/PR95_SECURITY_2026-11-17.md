## Picomatch mitigation

[GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf) affects
picomatch through 4.0.7. The npm registry and advisory had no published fixed
version at review. The locked installation has one copy, used through tinyglobby
by file discovery/lint tooling. Avoid an uncontrolled dependency upgrade.

`scripts/tooling/picomatch-security.mjs` runs after the existing install hook.
It conservatively literalizes repeated extglobs whose bodies contain `*` or `?`,
including single-branch cases such as `+(*)` and `+(*a)`. This deliberately narrows
that glob feature, including when recursion limits are disabled. Ordinary glob
stars, brace alternatives, and literal extglobs retain matching. It is a local
mitigation, not an upstream release or a claim to fix every possible regex issue.

The original/patched parser SHA-256, package version and exact lockfile layout are
pinned. Unknown source/layout fails installation. The audit verifies the installed
patched bytes independently and fails if they are absent or modified. Only this
exact advisory and high findings derived from it are treated as mitigated. Other
high/critical causes still fail, including additional advisories on picomatch or
its parents. Lower-severity findings remain visible under the existing threshold.
Original npm reports and counts remain unchanged in audit artifacts.
