# Express 5 backend modernization

The owner's renewed request is a Next.js-only frontend and a maintained Express backend, with obsolete dependencies/code removed after replacement parity. This is repository work on focused branches; master auto-deployment and hosted acceptance remain gated. No production data, fields, media or provider configuration is contracted by this change.

Registry verification on 2026-10-04 reports Express 5.2.1, Next 16.3.8 and Mongoose 9.10.4 as stable. Next is already current. This focused change pins the retained backend to Express 5.2.1, matching the modular API; database and runtime configuration upgrades are separate changes.

Reviewed [official Express 5 migration guidance](https://expressjs.com/en/guide/migrating-5/): native rejected-promise forwarding replaces mutation of private router handler stacks. The production boundary already explicitly uses simple query parsing and strict reconstructed filters; no writable query dependency exists. Fixture catch-all paths use named wildcards including the root. Inventory tests/fixtures use `app.router` rather than removed `_router`. Added a returned-promise failure regression proving redacted responses and continued liveness.

Removed confirmed-unused direct cors, exif, express-async-handler, express-validator and web-push declarations/imports. The explicit authenticated CORS boundary remains. Push delivery implementation/configuration is still a separate gate; removing an unused declaration does not prove delivery. Node `randomUUID()` replaces uuid while preserving UUID filenames and all surviving references. Deleted the unreferenced keep-alive script and node-fetch dependency; the application never imported that script. Axios/CSV/Drive/Mongoose remain until their maintained replacements are verified. No mass dependency upgrade was used.

The backend lockfile install now resolves 193 packages and reports zero vulnerabilities. Local checks passed: 103 API/security, 36 real disposable MongoDB/load, 67 unit, 7 release-gate and 29 compiled Chromium regressions, lint/typecheck, isolated Next/API build and three lockfile audits. Real commerce/stock/order/recovery/staff/media/provider behavior remains covered. All twelve production journeys, backup/restore, credentials, deployed artifacts, provider delivery, SEO and observed reconciliation still require hosted evidence.

Rollback uses the prior compatible application artifact and lockfile; no schema/backfill is needed. Preserve default-deny authorization, bounded parsers, transactional commerce, media references and notification contracts. Do not merge to master or trigger production while hosting acceptance is incomplete.
