# Staff order push delivery

This held candidate adds generic staff push to the persistent Express service. It is disabled by default. Explicit ADMIN_PUSH_ENABLED=true requires ADMIN_PUSH_SUBJECT (mailto contact), matching ADMIN_PUSH_PUBLIC_KEY / ADMIN_PUSH_PRIVATE_KEY and the same public key in the Next server configuration. Keys are supplied by the operator; startup never generates or rotates keys. The private key remains API-only. Existing exposed credentials still require documented rotation and affected browsers may require resubscription. Real browser/provider delivery remains unverified.

Maintained TypeScript validates HTTPS provider destinations, canonical base64url key sizes and valid P-256 subscription points. The retained authenticated subscribe/unsubscribe URLs and current-user ownership remain. Caller-supplied userId is ignored. Standard web-push 3.6.7 generateRequestDetails signs VAPID offline, following its [official API](https://github.com/web-push-libs/web-push/blob/master/README.md). Native fetch sends one cancellable POST with a ten-second deadline, four in-flight slots, no redirect and no adapter retry. Transport ignoring cancellation retains its slot until it settles. TTL is ten minutes, topic is almina-orders, and the message has no payload: browser workers show only a generic order update, without customer, medication, order or URL data. Provider acceptance is not browser delivery or staff acknowledgement.

Activation creates one additive notification_controls staff-order-push-v1 record before accepting HTTP traffic. Its original enabledAt excludes historical jobs on first activation and survives restarts. Re-enabling intentionally resumes jobs created since that activation; review pending age before re-enabling after a long pause. No core checkout or email outbox fields/states change. The worker derives push work from committed order_outbox jobs, one current eligible subscriber per tick, with a separate sixty-second lease/cursor and database-operation deadlines. Administrators are eligible; role=user staff must match the persisted customer city. Disabled/unknown roles are excluded. Authorization and the exact subscription are rechecked before attempting a send. Scanning uses ObjectId order, including the retained driver's separate BSON constructors. This is current staff eligibility at processing time, not a fabricated historical recipient snapshot; accounts created after the scan cursor may receive the generic update.

Majority-persisted staff_push_deliveries receipts bind a source job, user and subscription digest. A receipt claims exactly one attempt. Acceptance is persisted before advancing the source cursor; cursor failures resume without provider replay. Network timeout/unknown response or a process loss in sending becomes uncertain, requiring operator review without blind resend. A known 429/5xx rejection retries with exponential ten-second to one-hour backoff, at most eight attempts. Other rejection fails the receipt. A 404/410 removes only the exact old subscription, preserving a concurrent replacement. An accepted receipt means accepted by the provider, not delivered; at-most-one attempt after an unknown outcome deliberately favors avoiding duplicate effects over guaranteed delivery. The generic shared topic may coalesce pending notifications; push remains supplemental to the durable order list and authenticated realtime path.

The SMTP queue is independent. Provider failure never edits orders, inventory, confirmation state or checkout receipts. stop() stops new claims and awaits the active bounded attempt before the existing service drain closes MongoDB. Initialization failure closes MongoDB and fails startup. Operations exposes aggregate push receipt counts and PUSH_DELIVERY_REVIEW for failed/uncertain, stale sending/retry, invalid/missing-order jobs, or post-activation jobs older than ten minutes. These are review candidates, not an automatic retry or receipt deletion instruction. Additive index planning covers claims, receipt review and staff scope; no production indexes are automatically applied. Hosted query plans, queue throughput at representative staff counts and external alert collection remain acceptance gates.

Validation: real SDK request signing without a real send; strict key/destination/config tests; provider rejection/network/deadline/concurrency tests; disabled startup without DB access; actual retained subscribe ownership/CSRF/RBAC and generic worker tests; four disposable MongoDB cases with the actual retained driver's distinct BSON classes. They cover first activation/history exclusion, city/role scope, competing workers, active drain, eight bounded retries, unknown-response quarantine, conditional expiry, acceptance before a failed cursor write, and stalled-send recovery. The complete suite passes lint/typecheck, 82 unit, 104 API/security, 45 mandatory disposable MongoDB/load, seven release-gate and 42 compiled Chromium tests, foundation build and both lockfile audits (zero high/critical). Lockfile deduplication changed no existing package versions.
