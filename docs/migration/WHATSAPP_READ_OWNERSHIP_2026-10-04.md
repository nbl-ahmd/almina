# Bounded WhatsApp read ownership

All retained WhatsApp recipient, poster, report, conversation and public poster-reference reads now run through maintained TypeScript instead of Mongoose models. Existing authenticated URLs, administrator authorization, opt-out values, exact recipient strings, response arrays/object fields, Drive folder and published poster URLs remain. The default list page is now 25 (maximum 100, bounded offset 10,000); raw database predicates, unknown/repeated query fields and malformed parameters fail before database/provider work. Next already requests bounded list pages. Any still-running external legacy client that relied on an omitted limit returning the whole collection must adopt explicit pages during hosted compatibility verification.

Conversation reads return the latest 25 messages by default, at most 100, in chronological order within a page. messageCount/messageOffset/hasOlderMessages are additive presentation fields. Offset counts backward from the newest stored message; every older message remains available through explicit Older/Newer links, direct navigation and reload. Message offsets are bounded at 100 million (beyond any MongoDB document array capacity), avoiding the collection-list offset ceiling cutting off stored conversation history. Empty/beyond-end pages return an empty messages array. Concurrent appends can shift page boundaries; this is not a historical snapshot export. No conversation or message is deleted, trimmed or rewritten. Internal provider/delivery receipt fields are excluded from conversation and recipient projections. Reports retain the previous last-100-broadcast window per report; that existing limit is not presented as full delivery history.

Public raster poster filenames are bounded and validated before Drive access. Archived posters remain resolvable for already-sent templates while administrator poster lists hide archives. Missing references return 404; provider/database failures use redacted errors. Three now-unreferenced Mongoose schema files are removed after both writes and reads moved to maintained native modules. This removes source scaffolding, not collections, fields, documents, indexes or surviving images. Historical index behavior remains explicitly disabled at startup; only additive non-unique lookup index planning is supplied. Existing from/name duplicates need operator review, never automatic repair or a new uniqueness constraint.
