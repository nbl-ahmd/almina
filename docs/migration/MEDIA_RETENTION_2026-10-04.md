# Signed uploads and reference-preserving archive

`POST /api/media/products/:id` is administrator-only with independent server authorization, CSRF, multipart size/count limits, decoded MIME/pixel validation and bounded Sharp raster conversion. The API signs fixed Cloudinary parameters with SHA-256: image upload, WebP, a stable receipt-derived product namespace, timestamp and overwrite=false. No browser receives the API secret. Both upload and resource reconciliation use fixed Cloudinary HTTPS destinations with redirects forbidden. Responses are bounded to 64 KiB, checked for raster dimensions/bytes/account/public ID/version, and upload response signatures are verified. Implementation follows [authentication signatures](https://cloudinary.com/documentation/authentication_signatures) and [response signatures](https://cloudinary.com/documentation/signatures).

Activation requires `CLOUDINARY_UPLOAD_ENABLED=true`, configured `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY` and rotated `CLOUDINARY_API_SECRET` on the retained API. The website needs only the account name, including at build time for image/CSP patterns. Never use NEXT_PUBLIC for credentials. No live provider calls or hosting settings were changed by this work.

Next product editing provides a separate signed upload form. One to five raster files, at most 5 MiB each, replace the Cloudinary gallery. The API records actor/content-digest/retry-key intent before contacting the provider. Retrying the same files/key looks up the stable provider public IDs first, so a lost upload response can be reconciled without another asset. A 15-second shared deadline bounds provider work. Completed receipts replay without changing subsequent gallery or stock. A different actor/content/loaded revision conflicts. Reload retry requires reselecting the same files; local clearing never deletes server receipts or assets.

A transaction binds the media revision, history record and upload receipt to the product update. Prior scalar and array Drive fields and Cloudinary URLs remain in an append-only `media_history` ledger. Drive product replacements also record history/increment revision; category replacements preserve the prior asset and record references after successful upload. Retained product/category image routes resolve historical filenames through the ledger. No route automatically deletes surviving provider/local images. Failed uploads/conflicts can leave retained unreferenced assets; inspect receipt/provider manifests and reference history before any separately reviewed cleanup. Do not infer safe deletion from an empty current catalog.

Existing product/category/banner/poster DELETE URLs now archive their documents and media references. Product/category records remain available to historical order population; archived products cannot publish or change stock, archived categories cannot reenable, and archived records leave public listing/search/sitemap queries. Stock and commercial order history are unchanged. Next labels these actions **Archive**. There is no automatic destructive removal, unarchive endpoint or legacy-field contraction. Publishing recovery drafts now explicitly changes `published` alongside the retained disabled flag; archived products are blocked. Stable recovered IDs are accepted by the retained detail route, preserving existing PD URLs.

Fixtures use a synthetic provider; this does not attest live Cloudinary delivery or real provider credentials.

Hosted account permission/signature acceptance, recovered image/gallery/SEO rendering, original file URL inventory, fallback callers and rollback/traffic observations remain mandatory. Keep the store closed through recovery and keep production deployment blocked until hosted acceptance passes.
