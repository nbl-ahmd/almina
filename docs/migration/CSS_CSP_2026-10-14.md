# Development overlay and CSS cascade correction

The owner's screenshot showed an unstyled Next dev menu, missing-looking logo and a plain rectangular button. Inspection of the running Next 16.3.8 Turbopack app showed the overlay's open shadow root and 17 injected style nodes with no nonce. The proxy required a nonce for all style elements even during `next dev`. The widget therefore fell back to browser styling and lost its fixed compact presentation. App CSS does not cross the overlay's shadow-root boundary; Tailwind was not replacing the Next logo.

The version-matched bundled `next/dist/docs/01-app/02-guides/content-security-policy.md` explicitly separates development inline styles from production nonce styles. `stylesheetPolicy` now permits injected inline style elements only when **both** APP_ENV and NODE_ENV are development. Production/staging and compiled production-mode local tests retain nonce-only style elements. Script nonces/strict-dynamic, Origin/auth checks, frame restrictions and all commerce logic are unchanged. The dev indicator remains enabled; no Next internals are patched and no fake logo is introduced.

The wider cascade review also found unlayered semantic component rules, notably `.admin-app button`, taking priority over Tailwind utilities. Admin CSS and reusable storefront component defaults now occupy `@layer components`, below utilities in the existing theme/base/components/utilities order. The generic section spacing belongs to base. Secondary Cloudinary/recovery buttons now declare their surface background with readable text explicitly. Browser regression checks verify the secondary white surface and the primary utility padding actually win. Existing semantic components, tokens and the deliberate omission of Tailwind Preflight remain intact.

## Reproduce verification

Start the isolated demo with `npm run dev:demo`, then run `npm run verify:dev:styles`. The verifier refuses non-loopback origins, uses a separate browser context, blocks external requests and reads public routes/login only. It records stylesheet CSP violations and page errors, checks horizontal overflow and compact viewport-contained dev indicators at 360, 390, 768 and 1280 px, then opens the real Next menu and saves evidence in ignored `.verification-results/dev-styles/`.

The live run passed all 32 route/viewport combinations with no stylesheet CSP violations or page errors. The restored framework indicator measures 32×32 px, and the in-app browser screenshot confirms its logo, floating menu, spacing and icons. Next runtime config/session/compilation diagnostics are clear. The stylesheet-policy regression denies inline style elements for every other app/runtime environment combination. The compiled storefront smoke now separately asserts strict style elements, alongside existing script nonce and no-production-MCP checks.

During continued demo verification, OD5001 was cancelled through the authenticated Next admin gateway and the request repeated: both returned 200, stock restored 10 → 12 and remained 12, and the original receipt/total/order snapshots survived. The browser confirmed cancelled status. That check also revealed the admin status selector always defaulted to pending; its default now follows the loaded status and remounts after a committed status transition. The focused browser test checks dispatched status immediately and after reload. This is presentation only; server lifecycle authorization and transaction behavior are unchanged.

Final validation passes lint/typecheck, isolated production build, all 59 compiled browser cases (including accessibility, cascade and status-selector regressions), 235 sequential source tests, and foundation/storefront/raw SEO/production CSP smokes. The 35 ordinary-run database skips are covered by the preceding dedicated 53-test real MongoDB run; no database/domain implementation changed in this CSS follow-up. An initial concurrent reserved-port fixture timeout is rejected evidence; the sequential source rerun passed without changing the guard. Live Next config/session/compilation errors are empty. Proof of the actual restored in-app dev menu is `.verification-results/dev-styles/restored-menu.jpg`.

No production database, provider, credentials, deployment or framework dependencies were changed.
