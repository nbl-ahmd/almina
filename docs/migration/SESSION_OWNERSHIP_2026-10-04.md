# Maintained session ownership

The existing cookie-v2 session and browser-cookie policy now live in maintained TypeScript. Both HTTP contracts use that owner. The retained CommonJS import is a small compatibility export; the native TypeScript service no longer imports business logic from the retained security directory. Existing cookie names/flags, eight-hour expiry, token digests, password fingerprints, users/roles/city scope, logout/logout-all and fixed-window distributed quotas remain compatible. No account/password/session is migrated or overwritten and no credential is generated for an operator.

Historical cookie-v2 receipts continue to authenticate against current server-owned users. Unsupported roles, disabled/deleted accounts, expired receipts, changed password fingerprints, raw bearer tokens and duplicate cookies fail closed. Invalid stored identity fields now return unauthorized before inserting a new receipt rather than returning malformed staff data. Native BSON identifiers normalize across package copies; string-valued corrupted receipt identities are rejected. Identity cities preserve the existing string-only compatibility filter. No client role/city field can authorize a request.

Login validates bounded input before database access, uses the existing supported bcrypt cost range and dummy comparison, stores only a random-token SHA-256 digest and password fingerprint, and exposes the cookie rather than a browser token. Quota collection/key/window/limits and historical ModifyResult adapter remain; malformed/nonpositive/noninteger counters fail closed. Database operations use native query/operation deadlines. Cookie mutations retain exact allowed origins, custom CSRF header and cross-site rejection. This extraction does not claim a new password reset flow, real credential rotation or hosted authentication acceptance.

Final local validation: lint/typecheck, 91 root-only unit, 108 API/security/SDK, 50 mandatory disposable MongoDB/load and seven release-gate cases passed, along with the isolated foundation build and all 46 compiled Chromium cases. Both lockfile audits report zero high/critical. Focused tests cover unchanged historical receipts, malformed staff/receipt identities without new session writes, bounded login/token checks before database access, cookies/CSRF and both quota result contracts. Existing meaningful negative HTTP/RBAC, real disposable MongoDB staff revocation, combined-API session handling, realtime reauthorization and compiled browser login/order/admin flows remain required.
